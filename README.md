# Tab Chat

同じWebページ（URL）を開いているユーザー同士が、リアルタイムで **現在の接続人数** を確認し、**匿名でチャット** できるChrome拡張機能 + WebSocket(Socket.io)サーバーです。

- チャットUIは **ページ内に常駐するウィジェット** として表示されます（ポップアップはページをクリックすると自動で閉じてしまうため、この方式を採用）。
- チャット履歴は **DBに保存せず、サーバーのメモリ上のみ** で処理します（サーバー再起動・全員退室で消えます）。
- ルームIDは **開いているタブのURL** から生成します。YouTube / Amazon は一意IDを抽出し、その他はクエリを除いたURLを使います。

## 使い方（ウィジェットの操作）

| 操作 | 動作 |
| --- | --- |
| ツールバーの拡張機能アイコンをクリック | チャットパネルを **開く / 最小化** |
| パネル右上の `–`（hide） | 右下の丸いバブルに最小化。**接続は維持** され、人数に数えられ続け、新着メッセージは未読バッジで通知 |
| パネル右上の `×`（close） | **退室して完全に閉じる**（人数から抜ける）。再度開くにはアイコンをクリック |
| バブルをクリック | パネルを再表示（未読はリセット） |

- ページのどこをクリックしても **チャットは閉じません**（ページ内DOM描画のため）。
- 同じタブでページ遷移しても、開いた状態 / 最小化状態は自動で復元されます。
- YouTubeで別の動画に移動するなど **SPA内の遷移も自動検知** し、ルームを移動します。

## ルームID の決め方 (`extension/roomId.js`)

| サイト | ルームID の例 | 抽出方法 |
| --- | --- | --- |
| YouTube | `youtube:dQw4w9WgXcQ` | `?v=` または `youtu.be/xxxx` の動画ID |
| Amazon（各国ドメイン） | `amazon:B08XXXXXXX` | `/dp/`・`/gp/product/` などの ASIN |
| その他 | `https://example.com/path` | `origin + pathname`（クエリ・ハッシュ・末尾スラッシュを除去） |

## 動かし方

### 1. サーバーを起動

```bash
cd server
npm install
npm start
```

`http://localhost:3000` で待ち受けます。ブラウザで開くと `{"status":"ok", ...}` が返ればOKです。

> 開発中はファイル変更で自動再起動する `npm run dev`（Node 18+ の `--watch`）も使えます。

### 2. 拡張機能を読み込む

1. Chromeで `chrome://extensions` を開く
2. 右上の **デベロッパーモード** をON
3. **「パッケージ化されていない拡張機能を読み込む」** をクリック
4. この `extension/` フォルダを選択

> **更新時の注意**: コードを変更したら `chrome://extensions` で拡張機能の **「更新」(リロード) ボタン** を押し、さらに **対象ページを再読み込み** してください（コンテンツスクリプトはページ読み込み時に注入されるため）。

### 3. 使ってみる

1. 任意のページ（例: あるYouTube動画）を開く
2. ツールバーの **Tab Chat** アイコンをクリック → 右下にチャットパネルが出る
3. ヘッダーに現在の接続人数、下部にチャット入力欄
4. メッセージを入力して送信

## テスト方法（複数人をシミュレート）

1つのブラウザだけでも複数接続を再現できます。

1. **同じURL** を複数のタブ／ウィンドウで開く
2. それぞれのタブでアイコンをクリックしてウィジェットを開く（＝それぞれが1接続）
3. 人数が増え、片方で送信したメッセージがもう片方にも即時表示されることを確認
4. 片方で `×` を押すと人数が減ることを確認
5. `–` で最小化した側は人数に残ったまま、未読バッジが増えることを確認

さらに **別プロファイル** や **シークレットウィンドウ**（拡張機能をシークレットでも許可）を使うと、より実環境に近い形でテストできます。

### 動作確認のポイント
- YouTubeで **別の動画** を開くと自動でルームが切り替わり、人数・チャットが分離されること
- Amazon商品ページで、トラッキングパラメータが違っても **同じASINなら同室** になること
- ページ内のどこをクリックしても、チャットが閉じないこと
- サーバーを再起動すると履歴・人数がリセットされること（メモリのみ仕様）

## 仕様上の注意・拡張ポイント

- **人数カウントの意味**: ウィジェットを開いている（または最小化している）間だけ接続します。`×` で閉じた人・ウィジェットを開いていない人は数えません。
- **CSPが厳しいサイト**: 一部のサイト（`connect-src` を厳しく制限しているサイト）では、コンテンツスクリプトからのWebSocket接続がブロックされる場合があります。その場合はステータス欄に「サーバーに接続できません」と表示されます。本格対応するには background(Service Worker) 側にSocket接続を移し、メッセージ中継する設計に変更してください。
- **匿名名**: サーバーが入室順に `ゲスト1, ゲスト2, ...` を採番します。
- **本番運用**: `SERVER_URL`（`content.js`）と `manifest.json` の `host_permissions` を実サーバーURL（`wss://`/`https://`）に変更し、CORS設定を絞ってください。
- **アイコン**: `extension/icons/*.png` は1x1透明のプレースホルダです。任意の画像に差し替えてください。
